# 销售开单 API Gap

## 已确认的缺口

1. **可销售库存查询没有独立契约**：`/api/inventory/items?activeOnly=true` 只能排除部分终态，不能从接口层保证“可销售”。V2 只允许 `已入库`、`已上架`，并将其他状态标记为不可选择；后端未来应提供 `saleableOnly=true` 或销售候选专用接口。
2. **销售客户搜索已与 CRM 投影解耦（已解决）**：录单页通过 `/api/sales/customers` 直接查询 PostgreSQL 客户档案，并只要求 `sales_add`。CRM 主体表是增强读模型，不再决定客户能否被搜索和关联；这避免历史漏同步或无 CRM 菜单权限导致客户消失。
3. **收款账户搜索依赖财务权限**：销售开单的支付账户读取要求 `settlement_accounts`，当前权限模型没有独立的“销售收款账户可读”能力。前端按 403 显示账户不可用，不伪造账户。
4. **创建销售单是型号级预留**：创建接口会忽略明细中的物理库存绑定并在出库阶段绑定 SN。V2 的库存候选选择用于确认商品型号和可售状态，提交时明确发送空 `inventoryId`，不假装已经锁定某张卡。
5. **销售单缺少独立详情接口**：当前 V2 详情页和编辑页通过 `/api/sales-invoices` 的精确 ID/单号查询复用分页读模型，并在前端 Adapter 做权限裁剪；后端仍应提供按 ID 的正式详情契约，避免详情依赖列表查询。
6. **字段级权限只有成本/利润**：现有权限返回 `showCost`、`showProfit` 与菜单权限，没有折扣、费用、账户、价格的细粒度字段权限。V2 不新增权限语义。
7. **销售枚举没有配置接口**：渠道和支付方式只能沿用旧销售单已存在的后端枚举；若未来要由管理员自定义，需新增只读配置契约，当前前端不把静态兼容枚举当作远程数据。
8. **销售单没有附件和独立收款备注字段**：本轮以既有 `remarks` 兼容销售/收款说明；附件能力需要后端提供关联实体、上传鉴权和创建/补充接口后再接入。
9. **服务端当前主要返回业务级错误**：未发现结构化字段错误数组。前端已兼容未来的 `error.fields` / 校验数组并回填 RHF 字段，当前仍以页面级错误消息为主。
10. **销售列表没有服务端分页和筛选接口**：V2 正式销售列表只能读取 `/api/sales-invoices`。当前 TanStack Query 按账号与成本/利润权限隔离缓存，Adapter 先裁剪敏感字段，再在前端执行 URL 搜索、渠道、收款、出库、日期、排序和分页；页面不会把这套兼容行为标成服务端分页。
11. **销售列表没有独立摘要接口**：单数、件数、销售额、待收款、待出库和利润由已裁剪 Domain Model 汇总。后端未来应在专用列表响应中返回权限裁剪后的摘要，避免数据增长后客户端下载全量集合。
12. **销售详情仍缺少独立接口**：V2 已提供 `/sales/:id` 详情页和 `/sales/:id/edit` 编辑页，但读取仍由列表读模型精确定位；后端应提供按 ID 读取并包含权限、出库、收款、售后和版本信息的详情契约。
13. **销售编辑缺少乐观锁字段**：现有 PUT 只接受严格的 partial 销售单字段，没有 `recordVersion` / `updatedAt` 条件写入。V2 依赖服务端现有出库、退货和收款冲突校验，不在前端伪造版本控制；多人同时编辑仍可能出现最后写入覆盖，后端应补充版本条件和 409 语义。
14. **关联出库库存数量不是销售单字段**：前端 Adapter 暂按现有结构化 `salesInvoiceId` 和精确历史备注规则计算，只用于事实展示；未来应由销售列表/详情接口返回权威关联数量和出库阶段。
15. **销售出库池没有专用读取接口**：V2 仍需下载 `/api/sales-invoices` 后，在 Adapter 中裁剪待出库销售单、商品模板身份和可售库存。页面明确标注前端筛选/分页；数据增长后应提供按权限裁剪、可分页的出库任务接口。
16. **出库预检与正式确认共用规则但没有服务端预检接口**：前端使用既有商品身份规则提供扫码即时反馈，不能保证并发期间库存仍可用；`POST /api/sales-invoices/:id/outbound` 始终重新校验并作为最终结果。未来如需多人并发拣货，可增加只读预检或短期占用契约。
17. **销售出库没有结构化失败明细**：当前服务端主要返回整单业务错误，例如未扫码数量或库存不足数量，无法逐行标识失败原因。V2 保留扫码内容并显示服务端消息，不伪造字段错误。
18. **摄像头扫码依赖浏览器能力和安全上下文**：本机地址或 HTTPS 才能访问摄像头；不支持原生条码识别的浏览器需要扫码枪/手动粘贴。该限制属于客户端运行环境，不要求修改出库 API。
19. **销售编辑的媒体/图片仍不是销售单能力**：编辑页不会覆盖或伪造不存在的销售附件；如需附件，后端应提供关联实体、上传鉴权和补充接口。

## Adapter 兼容策略

- 页面不读取原始响应字段，所有接口响应先经过 DTO 和 Adapter。
- 销售客户候选始终返回客户档案 ID；不会把 `CRM-*` 归一化主体 ID 写入旧销售存储。
- 未来后端补齐候选接口或字段级权限时，只需替换 endpoint/adapter，不改销售表单组件。
