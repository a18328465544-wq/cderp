# 手机端 UI 视觉复审与方案选择

2026-10-08。仅审查、设计方案与本地文档；没有修改应用源代码，没有上线。

## 当前目标

面向二手硬件交易商的手机 ERP。沿用 Shopify 式商业任务组织、Linear 式克制层级、Square 式搜索/扫码入口；保留现有五个手机导航、权限、API、草稿保活、共享表单和金额/库存/退货规则。桌面页面不重排。方案沿用现有 Inter/PingFang、蓝白灰、400/500/600 字重令牌。

官方功能参考（不是对第三方应用的实际视觉审计）：

- [Shopify app](https://help.shopify.com/en/manual/shopify-admin/shopify-app)：手机处理订单、目录与经营数据。
- [Linear Mobile navigation](https://linear.app/changelog/2026-01-22-customize-your-navigation-in-linear-mobile)：底部导航优先覆盖日常工作流。
- [Square barcode workflows](https://squareup.com/help/us/en/article/7992-automate-item-creation-with-square-for-retail)：条码/搜索与商品操作结合。

## 本轮实际证据

使用独立浏览器 Tab，390×844，本地 127.0.0.1:3020 预览。预览使用明确的 LOCAL-ONLY 测试数据，业务写请求禁用；没有提交销售单、创建客户或连接生产数据库。以下文件都是本轮新捕获并重新打开检查过的截图，不复用旧验收。

### 1. 客户列表：可用，视觉结构需要重做

![客户列表](/private/tmp/erp-mobile-v2-evidence/design-audit-customers-20261008.jpg)

- 优点：五个主入口清楚；搜索、筛选、详情和新建入口真实存在；S 级核心身份和金额可辨认。
- 问题：外层列表卡片套内层列表卡片；标题计数、排序计数、底部分页计数重复；统计展开入口独占一段首屏。只有一个客户时，容器装饰比业务信息占屏更多。
- 建议：单一列表表面，细分隔线；合并结果计数/排序；搜索固定在业务标题下；核心/S 等级维持文字标记。分页不改变服务端分页语义，不改为假全量列表。
- 可见无障碍风险：搜索 placeholder 较长，在手机宽度下被裁切，不能作为完整操作提示；浅灰次级信息需实测对比度。不能仅凭截图判断 WCAG 合规。

### 2. 客户详情：完整，重点不突出

![客户详情](/private/tmp/erp-mobile-v2-evidence/design-audit-customer-detail-20261008.jpg)

- 优点：原客户详情全屏呈现，编辑入口固定在底部；账务事实、身份和状态没有被移动布局删掉。
- 问题：页头和内容重复客户名称；主要交易信息与普通 metadata 都采用相近条目权重；往来与联系区之间的大留白削弱连续阅读。
- 建议：页头负责返回与上下文，正文一次展示客户身份；累计交易和余额优先，普通资料折叠；统一摘要与明细的间隔节奏，不添加不存在的联系/交易接口。
- 可见无障碍风险：小号浅色字段依赖颜色层级，需测试对比度、系统放大和 VoiceOver；本轮没有声称这些已通过。

### 3. 销售开单草稿：有工作流基础，商品行过高

![销售开单](/private/tmp/erp-mobile-v2-evidence/design-audit-sales-new-20261008.jpg)

- 优点：客户/商品与结算拆成两步；底部金额与下一步始终可见；原数量、单价、更换与删除入口保留。
- 问题：单个商品的标题、metadata、字段标签、输入框、小计与移除占较多纵向空间，多商品时需要频繁滚动；添加商品位于模块右上，单手连续录单的触达可以改进。
- 建议：不删单价和数量的业务能力；统一商品行，突出标题和可编辑金额；补充信息维持原入口；下一步及主要添加动作使用一致的底部操作策略，避免多条固定栏抢空间。
- 限制：只操作本地草稿，没有下单和入账。本轮没有测试真机软键盘、相机权限或扫码识别率。

## 视觉选择

以相同客户列表屏幕生成三种独立结构：原生经营列表、单手操作、客户优先级。它们共用现有颜色/字体/导航，不引入新的后台能力。效果图中的扩展示例客户都是设计用虚构数据，不作为真实客户和账务证据。

按产品设计流程，先展示三个效果图，由用户选择后再实施，避免未确认的整套视觉替换。选定后分组落实：共用手机基础组件 → 客户/库存列表与详情 → 采购/销售开单 → 质检/出库/退货 → 其余已有页面。每组都需要当前构建、尺寸/长内容/弹层验证以及桌面回归。

三张独立效果图已经各自在聊天中展示一次。以下编号严格按实际显示顺序绑定，供后续实施查找，不是实现验收：

## 后续实施状态 · 2026-10-08

首组客户目录已落地：底部搜索/新建、单层记录、合并核心/S快捷筛选、共享排序及紧凑分页。实际采用现有客户接口、权限、分页和原新建窗口，未修改生产数据。桌面呈现保留。实现与截图验收详见 `MOBILE_UI_THUMB_20261008.md` 及项目根 `design-qa.md` 的最新章节。

当前不是全部页面的第二方案改造完成：库存、开单、仓库及其他页面沿用已有移动端，待客户目录视觉确认后按上述组别继续；不要将这一阶段当作全系统上线或真机验收。

## 证据边界

本轮三屏复审不是所有页面的全面验收。没有新运行 lint、构建或测试，也没有宣称本轮已经优化或上线。后续实现须保留所有已有未提交改动，不将设计选择扩展为业务、权限或数据结构变更。
