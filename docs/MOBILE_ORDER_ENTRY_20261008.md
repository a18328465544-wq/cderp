# 手机销售、采购开单验收 — 2026-10-08

## 范围与边界

按本轮移动开单审查结果实施：销售、采购新建单页面及其共享选择器、商品行、付款组件。编辑单据仅接入共享付款就绪校验，并修正销售编辑时已选客户导致更换搜索不执行的条件。

保留现有 RHF 表单、商品/库存候选接口、领域校验、权限、幂等提交和工作区保活。没有新增手机业务数据模型、修改后端业务、重写新建商品窗口，也没有部署、提交或推送代码。现有工作区有大量历史未提交改动，本轮没有清理或回滚它们。

桌面继续使用原采购/销售表格，默认 4 行；手机只呈现有内容的行，添加时复用空行，不足再追加。

## 已实施

- 来源/客户与商品为第一步，结算为第二步；标题提示明确为“草稿 · 切页保留”。
- 选中客户/供应商后可直接更换，取消选择不会先清空原对象；候选的实际选中状态与键盘活动状态分离。
- 添加商品直接打开现有选择器；不再先插入一张空白编辑卡再点击选择。采购“新建商品”仍使用原系统商品规格模板窗口，等待选择器关闭后再打开。
- 手机商品行直接编辑单价、数量，显示完整名称、可用库存与小计；补充信息用共享底部弹窗承载备注、预估售价或整行成交金额。
- 数量允许直接输入；清空后点加号从 1 开始。320 宽度下为加减按钮及输入保留足够空间，不再显示重复的浏览器数字旋钮。
- 收付款明确为全额、未付/未收、部分三档。移除销售 50%、采购 40% 的自动猜测金额；部分金额必须显式填写且小于可付/可收总额。
- 全额模式跟随商品总额更新；部分模式保留实际金额，金额变得不合法时提示并阻止提交，不静默重写。
- 结算只突出本单总额、实际付款、剩余欠款、账户和单一提交动作；金额明细、物流与附件等可选内容折叠。手机没有供应商可用余额时隐藏空抵扣区域。
- 编辑单据的完整编辑模式也接入部分收付款就绪反馈，提交回调另有保护；受限元数据编辑不受影响。
- 电脑窄结算侧栏中的三档付款按钮整行显示，避免竖排文字；表格结构未改。

## 实测

使用本地 `127.0.0.1:3020` 的合成预览数据。业务写入统一返回模拟 409，不连接真实账务数据库，不创建真实采购/销售单。

| 场景 | 结果 |
| --- | --- |
| 空单无客户/来源及商品 | 下一步禁用，显示对应领域校验原因 |
| 添加商品、改价、直接输入数量 | 同步更新行小计与总金额 |
| 更换客户后取消 | 原客户保持不变 |
| 采购快速新建商品 | 打开原商品规格模板窗口；取消后仍可继续选品 |
| 采购追加到第 5 行 | 超过默认空行后正常追加，可继续录入 |
| 未收款/未付款 | 金额为 0，不猜测部分款，现金账户不强制要求 |
| 部分收款/付款未填金额 | 显示明确原因，提交禁用 |
| 销售实际收款 120，商品总额由 540 改为 600 | 收款保持 120，剩余欠款更新为 480 |
| 采购总额 440、付款 123 后切到销售再返回 | 商品及付款保持，欠款 317 |
| 模拟销售/采购提交冲突 | 显示冲突信息，原表单及实际付款保持 |
| 320 宽度 | 无页面横向溢出；数量控件右边缘未超过编辑区 |
| 390/430 宽度 | 清单、选择器、结算、底部动作和主导航可用 |
| 1440 宽度 | 销售/采购各保留 4 行原表格；付款按钮不换成竖排 |

### 保留限制

- 当前工作区草稿为内存保活：切页/切 Tab 保留，整页刷新仍会清空。本轮没有扩展为浏览器持久化或服务端草稿，提示已改为“切页保留”。
- 浏览器尺寸模拟不等于真机软键盘、扫码摄像头与 iOS 安全区验收；这些仍需真机验证。
- 本轮预览供应商余额为 0，正余额抵扣沿用领域结算与已有测试，但没有在真实账户上执行抵扣或入账。
- 本轮尚未上线；合成预览提交必然失败，不能当成线上业务录单入口。
