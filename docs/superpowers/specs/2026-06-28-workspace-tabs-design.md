# ERP 顶部多标签工作区设计

## 目标

在现有 `currentTab` 页面切换机制之上增加轻量顶部标签工作区，让用户能够快速切换已打开的 ERP 页面。标签不是浏览器窗口或弹窗，不改变任何业务页面、业务接口和页面组件的内部逻辑。

## 现状

- 页面由 `src/App.tsx` 中的 `currentTab` 控制，没有引入 React Router。
- 左侧菜单和页面权限统一来自 `src/utils/menu.ts`。
- 已访问页面通过 `mountedTabs` 保持挂载，以保留录单页面的临时状态。
- Nginx 当前按单页应用方式提供前端，因此引入真实 path 路由会扩大部署和回归范围。

## 路由方案

采用 Hash URL，同步格式为 `/#/<menuId>`，例如：

- 首页：`/#/dashboard`
- 销售开单：`/#/sales_add`
- 单卡/SN库存：`/#/inventory`

Hash 变化不会触发服务器路径请求，兼容现有 Nginx 配置。直接访问或刷新带 Hash 的 URL 时，系统在登录和权限加载完成后打开对应页面；无效或无权限的 Hash 回退到首页。

## 数据结构

标签只保存稳定菜单 ID，不复制名称和分组，显示信息始终从 `APP_MENU_ITEMS` 读取。

```ts
interface WorkspaceTabState {
  openIds: string[];
  pinnedIds: string[];
  recentIds: string[];
  activeId: string;
}
```

- `openIds`：按首次打开顺序排列。
- `pinnedIds`：固定标签集合，首页始终包含在内。
- `recentIds`：最近激活顺序，最新页面位于末尾。
- `activeId`：当前页面 ID。

## 持久化

- 使用 `localStorage` 保存标签状态。
- 存储键包含当前用户 ID，避免同一浏览器切换账号时共享无权限标签。
- 恢复时仅保留仍存在于菜单配置且当前账号有权访问的标签。
- 首页始终补回并固定。
- 存储损坏、浏览器禁用存储或旧配置异常时静默回退到首页。

## 标签行为

### 打开与切换

- 所有菜单跳转和页面内跳转统一调用工作区导航函数。
- 页面不存在时新增标签；已存在时只激活。
- 激活标签时更新最近使用顺序和 URL Hash。
- 浏览器前进、后退或直接修改 Hash 时同步激活对应标签。

### 数量限制

- 最多打开 10 个标签。
- 新增第 11 个标签前，关闭首次打开且未固定、非当前目标的标签。
- 如果全部标签均固定，则拒绝继续固定更多标签；普通新页面仍可替换最早未固定标签。

### 关闭

- 首页不可关闭。
- 关闭非当前标签不改变当前页面。
- 关闭当前标签后，优先切换到 `recentIds` 中最近使用且仍打开的页面；没有候选时回到首页。
- “关闭其他”保留当前标签及所有固定标签。
- “关闭全部可关闭标签”保留所有固定标签，并切换到当前固定标签或首页。

### 固定

- 首页默认固定且不可取消。
- 其他页面可通过标签菜单固定或取消固定。
- 固定标签显示 `Pin` 图标并排列在普通标签之前，组内保持原有打开顺序。

## 组件边界

### `workspaceTabs.ts`

纯函数与常量：解析/生成 Hash、恢复状态、打开、关闭、固定、权限过滤和数量淘汰。它不依赖 React，便于完整单元测试。

### `useWorkspaceTabs.ts`

负责 React 状态、`localStorage`、`hashchange` 和当前用户切换。向 `App` 暴露统一的 `navigateTab` 及标签操作。

### `WorkspaceTabs.tsx`

只负责标签栏展示和交互：

- 点击切换。
- 单个关闭按钮。
- 右键或标签操作菜单中的固定、关闭、关闭其他、关闭全部。
- 横向溢出时滚动，不挤压页面主体。

### `App.tsx`

继续负责业务页面组织和 KeepAlive，只把原有 `currentTab`/`setCurrentTab` 接到工作区 Hook。现有业务组件仍接收相同签名的 `setTab`，无需重写业务逻辑。

## 视觉设计

- 标签栏位于主内容区顶部、业务页面内容之前。
- 高度 38px，白色/中性浅灰背景，底部弱分割线。
- 标签字号 13px。
- 普通标签使用透明或浅灰背景；激活标签使用浅蓝背景、蓝色文字和底部蓝色指示线。
- 关闭按钮默认弱化，在标签 hover 或激活时明显显示。
- 标签最大宽度固定，长名称省略，避免挤压其他标签。
- 桌面端横向滚动；移动端同样横向滚动，不改变业务页面布局。
- 不使用重阴影，不增加大卡片或额外页面 Header。

## 权限与异常处理

- 无权限菜单不会恢复、打开或通过 Hash 访问。
- 账号权限发生变化时，立即清理失效标签并回到最近可用标签。
- 菜单 ID 不存在时回到首页，并修正 URL。
- `localStorage` 异常不会阻止系统进入。

## 测试

### 单元测试

- 首次进入只打开并固定首页。
- 重复打开同一页面不产生重复标签。
- 第 11 个标签淘汰最早未固定标签。
- 关闭当前标签切换到最近使用标签。
- 关闭其他和关闭全部保留固定标签。
- 无权限、失效和损坏的持久化数据被清理。
- Hash 与菜单 ID 可以双向转换。

### UI 回归

- 左侧菜单、首页快捷入口、单据编辑跳转均会创建/激活标签。
- 刷新后恢复打开标签和当前标签。
- 浏览器前进/后退与标签高亮同步。
- 标签栏不影响现有页面滚动、录单表单状态和侧边栏抽屉。
- 运行 `npm run lint`、`npm test`、`npm run build`。

## 非目标

- 不引入 React Router。
- 不改变现有业务 API、页面 ID 或权限协议。
- 不实现多窗口、弹窗工作台或可拖拽标签排序。
- 不在本次修改业务页面内部状态和业务逻辑。
