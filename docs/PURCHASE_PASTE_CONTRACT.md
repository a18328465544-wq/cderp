# Purchase Paste Contract（Frontend V2 Phase 3A）

## 支持格式

- 推荐 Excel / 表格 Tab：固定列或带表头均可；Tab 模式允许 `18,000`、`¥18,000`、`￥18,000`。
- 无表头固定列：`商品名称,采购价,预计售价,备注`，逗号模式金额必须是不含千位逗号的数字。
- 带表头 Tab：支持商品、品牌、型号、版本、显存、数量、采购价、预计售价、成色、质保、质保日期、库位、备注及项目现有别名。
- 多空格仅在存在可验证表头、列数一致且商品名称没有被空格拆开的情况下支持；否则整行拒绝。

## 明确不支持

- 无引号 CSV 中带千位逗号的金额，例如 `18,000`。
- 带引号转义的 CSV、CSV 文件上传、Excel 文件上传、OCR 和 AI 识别。
- 无表头多空格商品清单。
- 未匹配或多候选商品直接加入；本阶段不提供快速新增模板和模糊匹配。

## 处理规则

1. 文本先通过纯函数解析并展示预览，解析器不调用创建采购接口。
2. 默认值来自 `createPurchaseLineDefaults()`，解析器只覆盖用户明确填写的字段。
3. 商品只按标准化后的唯一严格匹配（商品名、完整身份、品牌+型号、型号）；多候选和未匹配必须人工选择现有模板。
4. 重复按商品模板/品牌/型号/版本/显存/价格/备注判断，只提示，不删除、不合并；同一批次每行最多展示一条同类重复提示，并注明其余数量，避免 50～100 行粘贴时渲染成数千条重复文案。
5. 预览编辑后重新校验，最终确认时再次校验；只有合法且已确认的行才一次性写入现有 `useFieldArray`。
6. 数量保留在线级表单模型中，不生成物理库存行、SN 或库存 ID，最终仍由 `toPurchaseRequestDto()` 展开。
7. 采购价录入遵循 `purchase_add` 和现有手工表单语义，不能用 `showCost` 擅自阻断本次采购价输入；预计售价遵循当前表单的 `showProfit` 字段展示规则。

## 限制

- 最大 100,000 个字符、500 行，超限明确报错且不静默截断。
- 所有粘贴内容按纯文本处理，不执行 HTML 或脚本。
