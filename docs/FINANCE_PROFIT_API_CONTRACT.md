# 销售利润 V2 API Contract

## 当前真实链路

销售利润页复用现有 `salesApi.list()`，请求：

```text
GET /api/sales-invoices
```

响应先经过 `adaptSalesListState()`，再进入 `selectFinanceProfitReport()` 做页面内筛选和聚合。页面不直接读取原始状态快照，也不直接调用 `fetch`。

## 可用字段

- 销售单：单号、日期、客户、渠道、经办人、数量、销售额
- 明细：商品名称、成色、数量、售价
- 成本与毛利：仅在当前账号拥有 `showCost` / `showProfit` 且服务端返回字段时使用

按商品维度时，明细售价、成本和利润按数量聚合；按客户、渠道、经办人维度时，使用销售单级 `totalCost` / `totalProfit`。缺少权限或字段时显示“—”，不从销售额推算利润。

## 筛选与导出

关键词、日期范围、分析维度、分页状态同步到 URL。由于现有接口返回销售领域快照，当前筛选、聚合、分页和导出均在前端完成，并在页面上明确标注“销售领域快照 · 前端筛选与聚合”。导出范围是当前筛选结果的全部分组，不是假装的服务端全量报表。

## API Gap

当前后端尚未提供销售利润专用接口，因此暂不具备：

1. 数据量增长后的服务端日期/维度聚合；
2. 服务端排序、分页和全量报表导出；
3. 服务端统一的利润口径/退货冲销口径说明。

本轮不修改 FastAPI、数据库或权限规则。后续若销售单量增长，应优先补充专用报表接口，再由前端移除状态快照聚合降级。
