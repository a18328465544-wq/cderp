# Finance Ledger API Gap

## 已补齐：服务端日期范围与模糊搜索

账户流水专用接口现在支持 `dateStart` / `dateEnd` 和 `keyword`。日期范围在服务端校验后参与分页前过滤，关键词会在备注、客户、供应商、关联单号、账户、业务类型和经办人字段中做大小写不敏感匹配，避免前端只筛当前页造成统计失真。

后续如数据规模增长，应在数据库层为发生时间与可搜索字段增加索引，并保持该查询契约不变。

## P2：缺少服务端排序

当前接口没有排序字段和方向契约。正式表格关闭了排序交互，避免把单页排序误认为全局排序。

建议未来支持白名单字段（发生时间、收入、支出、变动金额、变动后余额）和 `asc` / `desc`。

## P2：缺少全量统计接口

当前列表响应只有分页元信息，没有筛选范围的收入、支出、净变动、账户数量和异常数量。页面只展示当前页汇总。

建议未来增加独立 summary endpoint，或在列表 `meta.summary` 返回服务端全量聚合。

## P2：缺少完整筛选导出

没有专用导出接口，前端只能诚实导出当前页。

建议未来提供受 `settlement_ledger` 权限保护、复用同一筛选契约的流式 CSV 导出。

## P3：账户筛选与账户权限独立

具备 `settlement_ledger` 但不具备 `settlement_accounts` 的用户无法安全获得完整账户 ID 候选。当前页不会请求账户余额接口，并禁用账户下拉。

建议未来如产品确需该组合权限，提供只含 `id + name` 的最小账户候选接口，不包含余额和敏感账户资料。
