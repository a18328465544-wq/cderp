# Finance Accounts API Gap

## 当前已采用的安全降级

1. **账户列表没有服务端筛选、排序参数。** V2 Endpoint 按 `meta.total` 逐页完整读取账户集合，再在前端筛选。账户属于低基数主数据；若未来账户规模显著增加，应补服务端关键字、类型、状态和排序参数。
2. **没有账户编辑接口。** V2 不展示伪编辑入口，不通过状态快照或其他写接口绕过后端。
3. **没有账户详情接口。** 当前列表行已经包含账户档案字段；详情抽屉使用该 Domain Model，并独立读取账户流水。
4. **没有账户汇总与趋势接口。** 页面只展示可由账户集合精确计算的账面、可用、冻结和实盘差额；不把最近 20/200 笔流水样本伪装成完整的今日收支或趋势。
5. **没有“删除前引用检查”接口。** 前端只能说明规则，最终删除由后端检查并返回明确错误。
6. **实盘核对没有独立权限字段。** 当前沿用服务端 `settlement_accounts` 权限；V2 不自行发明 `account_reconcile` 权限。
7. **没有乐观并发版本。** 两人同时核对时以最后一次服务端成功写入为准；未来可增加版本号或 `updatedAt` 条件写入。

## 不属于本轮范围

- 不修改后端、数据库、API 或权限规则。
- 不新增期初余额调整、账户启停、账户编辑或余额直接修改。
- 不通过前端计算替代账户流水、资金调拨与余额联动的后端业务动作。
