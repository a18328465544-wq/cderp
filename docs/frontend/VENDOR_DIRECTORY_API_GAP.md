# 同行档案 API Gap

## 1. 缺少独立列表接口

页面当前需要独立、权限裁剪后的同行列表、服务端搜索、筛选、排序、分页和汇总；现有后端只有 `/api/vendors`。

前端可通过 Adapter 安全隔离页面模型，但无法避免整库响应的传输和浏览器内存成本。当前采用诚实降级：前端仅对已加载集合处理，并在页面标注“真实整库”。未来建议提供独立只读接口，本轮不修改后端。

## 2. 敏感字段仍由整库响应承载

Frontend V2 在 `showProfit=false` 时不会把平均利润投影到 Domain Model、表格、详情或导出；但若 `/api/vendors` 本身仍返回 `avgProfit`，前端隐藏不等于服务端数据安全。未来应由后端在响应前按权限裁剪。

## 3. 导入缺少批量事务接口

V1 有导入入口，但现有后端没有明确的同行批量校验、幂等和事务写入接口。Frontend V2 仅提供 CSV 导出，不通过循环调用单条创建接口伪造批量导入。

## 4. 删除采用业务阻止而非停用

现有删除接口会阻止删除已关联采购或销售单据的同行，但没有独立“停用”状态。页面提示用户通过备注或 R 级标记风险；未来如需停用，应由后端提供正式字段与审计语义。
