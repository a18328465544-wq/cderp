# CRM Workspace API Gap

以下是现有接口限制，仅用于后续后端规划；本轮没有修改 FastAPI、数据库或权限。

| 缺口 | 当前事实 | V2 前端处理 | 后续建议 |
| --- | --- | --- | --- |
| 业务阶段不能在关系化列表中筛选 | `/crm/accounts` 的主体 `status` 当前同步为 `active`，并非“线索/跟进中/已成交” | 业务状态只展示；不发送无效 status、不做当前页前端假筛选 | 在关系化主体或商机查询中提供稳定的 CRM 阶段筛选字段 |
| CRM 汇总仍加载旧集合 | `/crm/summary` 从进程状态中的旧 customers/followUps/requirements 聚合，并返回完整集合 | Adapter 立即丢弃完整集合，只消费 totals 和 ownerSummary | 增加 SQL 聚合摘要接口，只返回权限裁剪后的统计 |
| 跟进写接口仍需要旧客户 ID | 关系化列表 ID 与旧 `customerId` 不同 | 只在存在 `legacyCustomerId` 时开放跟进；不猜 ID | 提供按 CRM account ID 写入跟进的领域命令 |
| 详情缺少关系化客户档案接口 | 当前只有列表行和时间线，没有 `GET /crm/accounts/:id` | 抽屉复用当前列表行，时间线独立 Query；不伪造联系人、订单或收付款详情 | 增加客户 360° 详情接口，返回联系人、机会、关联单据摘要和字段级权限 |
| 时间线只取前 50 条 | 当前页面使用独立 Query 读取第一页 | 明确只展示最近 50 条，不做假无限滚动 | 支持时间线分页或游标加载 |
| 关系化列表不支持客户端指定排序 | 服务端固定按 `updated_at DESC, id ASC` | 表格关闭排序入口，保持服务端真实顺序 | 增加白名单排序参数 |
| 敏感字段权限没有 CRM 专用契约 | 现有路由只有 `crm` 菜单权限，没有字段级联系人/成交额权限 | 前端只展示接口返回的 CRM 字段，不宣称 UI 隐藏等于安全 | 后端返回最终字段级能力并在 SQL/序列化层裁剪 |
