# 错误处理规则

## 统一类型

`src/services/api/errors/index.ts` 的 `ApiError` 是页面和组件识别请求错误的唯一类型。Client 将网络错误、HTTP 状态和后端 `{ error: { code, message } }` 统一转换。

## 状态处理

| 状态 | 处理 |
| --- | --- |
| 401 | 清理浏览器内存中的 CSRF 状态，回到登录状态，不展示旧业务数据；过期 HttpOnly Cookie 由服务端清除 |
| 403 | 显示无权限状态，隐藏受限操作和字段 |
| 409 | 保留表单，提示并发或业务冲突，要求刷新候选后重试 |
| 422 | 优先映射字段错误，无法定位时显示页面级错误 |
| 网络错误 | 显示可重试错误，不清空已有列表数据 |

## 查询

- 列表使用独立 Loading、Empty、Error、Retry。
- 后台刷新保留已有数据，避免闪烁。
- 详情 Query 独立处理加载和错误，切换 ID 时不能残留上一条数据。
- 过期请求由 Query signal 取消或由 Query 忽略竞态。

## 提交

- 提交中锁定按钮并防止重复请求。
- 失败保留用户输入。
- 成功后只清理当前表单并失效相关 Query Key。
- 不把服务器错误静默吞掉，也不凭前端默认值覆盖服务端事实。
