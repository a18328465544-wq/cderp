# 日结与异常 API Gap

## 已确认的差异

1. **菜单权限名称不一致**：前端历史菜单使用 `finance_closing`，但 `/api/finance/daily-closing*` 服务端要求精确的 `finance`。前端允许两者进入页面；只有 `finance_closing` 的账号请求接口时仍可能得到 403。这个权限范围问题不在本轮修改后端。
2. **列表接口没有服务端分页和筛选**：当前只支持 `limit`。V2 页面最多读取 30 条最近快照，再对已返回数据做日期、关键词和分页，数据量增加后需要后端补充 `page/pageSize/dateStart/dateEnd/keyword` 能力。
3. **异常没有明细关联**：快照只返回数量和金额摘要，不包含待复核流水、对账账户或应收应付单据明细。页面只展示摘要，并引导回资金驾驶舱或专用页面。
4. **写入口尚未迁移**：后端已有 POST 保存日结接口，但旧页面能力地图只有查询/复核列表，本次先迁移只读链路；如果要在 V2 暴露“登记日结”，应单独确认日期、备注、重复日结和并发语义。

## 前端降级原则

- 不伪造实时异常、资金余额或完整流水。
- 403、401 按统一 API 错误处理，不能用空数组掩盖权限失败。
- 历史快照的应收应付只作为日结时点数据，不参与当前余额计算。
