# 手机客户目录 · 单手操作方案

2026-10-08。用户选择实际显示顺序中的第 2 张设计。客户页为本次首个落地页面；不包含全系统第二方案改造或上线。

## 范围与实现

- 手机小于768px：紧凑标题/真实筛选总数 → 全部及核心/S快捷筛选/原排序 → 单层客户记录 → 底部搜索/新建 → 原五项主导航。
- 搜索44px、新建48px，文字/间距/颜色都引用现有Token；新建仍打开 `CustomerRecordDialog`，详情仍使用既有窗口。
- 复用 `ErpMobileRecordRow`，增加可选标题旁状态及金额说明；其他业务默认呈现不变。新增 `ErpMobileActionDock` 只负责手机活动Tab的呈现，不含权限、查询、金额或写入逻辑。
- `ErpDataTable` 的手机工具栏和紧凑分页均为可选参数。客户页使用同一个排序控制器、服务器分页、筛选序列化；每页20/50/100放在筛选面板，单页不重复显示页码框。
- 原核心身份固定S级，故设计中的核心/S两枚重复筛选合并；等级颜色复用桌面语义。不得从图片生成新客户等级、财务数据或前端分页算法。
- 底部栏为列表末尾预留空间，沿用已有键盘/安全区偏移；输入时隐藏新建，窗口/筛选打开时隐藏底部栏，避免和弹层操作混用。实际iOS键盘与非零安全区仍需真机验收。
- 平板768–1023px和桌面1024px以上沿用原布局/表格、搜索、统计、列设置和完整分页。本轮不修改后端、路由、数据结构或记账逻辑。

## 浏览器证据

运行实际本地构建产物，不是独立静态UI。隔离预览绑定127.0.0.1，测试姓名和金额明确为合成数据；全部业务写入拒绝，不连接生产数据库。

- 名称搜索、无结果、清空、核心/S、A级筛选，以及累计交易排序实际点验；参数归属原URL状态和API。
- 原新建窗口：模拟409失败后姓名保留，关闭恢复底栏；没有验证真实创建成功或写入数据库。
- 原详情正常打开；窗口内联系/往来信息可达。切库存后不残留客户搜索栏，返回客户保留筛选。
- 25条合成数据，20/页→第二页5条；改50/页回到第一页25条；滚到末尾最后一条完整处于固定操作栏上方。
- 320px长公司名及¥1,234,567,890金额无横向溢出；日期使用原值整体换行，不再从2026-中间拆开。
- 读取失败明确显示“加载失败”而非伪造0客户，可重试且保留搜索/新建入口。

六档尺寸为320/390/430/768/1024/1440×844；document scrollWidth等于请求宽度。手机操作栏125px，位于659–784，导航784–844；平板/桌面无手机操作栏及导航。1024/1440保留桌面表格。截图见 `mobile-v2-evidence/20261008/thumb/`。
