# 日期控件审查（2026-08-18）

## 范围

- 公共组件：`src/components/common/ErpDatePicker.tsx`、`src/components/common/ErpCalendar.tsx`
- 日期范围页面：财务总览、流水、日结、收入、支出、利润、资金调拨、客户资金、销售、采购、库存
- 运行态：`http://localhost:5173/`

## 运行态限制

当前会话停留在登录页，无法在真实登录态打开日期弹层；证据截图保存在 `01-auth-blocker.png`。以下结论来自当前代码、样式、路由筛选状态和测试审查，不冒充完整的登录后视觉验收。

## 主要发现

1. 日期弹层写死 `z-50`，低于全局 Tab `1000` 和抽屉 `900`，缺少日期/选项浮层层级 token。
2. 只有财务流水页把开始/结束日期互相绑定为 `min/max`；其他日期范围页允许选择反向区间，通常会进入空结果或异常查询。
3. 移动端公共 `FilterBar` 会把内容改成单列，但销售、采购、利润、客户资金、库存等页面仍把两个固定宽度日期按钮放在同一行，`w-32/w-36` 可能造成范围控件内部横向溢出。
4. 财务总览有反向/超长范围校验，但错误只用于禁用“应用”按钮和 `title`，没有可见的错误提示。
5. `ErpDatePicker` 会把非法值显示成占位符，但多个页面的 URL 解析只做 `trim()`，没有统一日期格式校验；可能出现 URL 有筛选、控件看起来未选择的状态。
6. 文档要求的 `DateRangePicker`/统一日期范围组件在当前 V2 源码中不存在；实际代码是单日 `ErpDatePicker` + 页面内重复拼接。已有 `dateRangePickerUtils.ts` 的范围、快捷词和自然日期能力也没有接入公共控件。
7. 客户资金页通过 `new Date()` 自己初始化日期范围，没有复用 `storeTime.ts` 的门店日期契约，跨 UTC 日界线时存在日期偏移风险。

## 建议顺序

1. 先补 `erp-layer-popover` token，并让日期/选择/列表浮层统一使用“低于 Tab、按场景高于内容”的层级。
2. 新建唯一的 `ErpDateRangePicker`，集中处理开始/结束关系、非法值、最大跨度、快捷范围、移动端布局和可见错误。
3. 所有列表和财务报表改为调用该范围组件；页面只传字段和值，不再自己拼接两个 `ErpDatePicker`。
4. 统一用门店日期工具初始化和比较日期，并补反向区间、非法 URL、390px 弹层定位与键盘操作测试。
