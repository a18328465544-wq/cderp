# 移动端共享 UI 尺寸适配

日期：2026-10-08。本轮仅本地实现，没有上线、提交或推送。保留工作区已有改动；没有改后端、权限、账务、录单状态或接口。

## 实际问题

- 客户页“更多页面操作”只有 20px 宽、44px 高。手机图标按钮的最小宽度被更高优先级的通用页头子项规则覆盖。
- 手机控件高度变量原来只放在 AppShell；Portal 中的表单没有继承，输入框退回桌面 40px。仅扩大文字不能解决触控尺寸不一致。
- 共用弹窗底栏在滚动正文之外，仍继承为正文内部操作准备的负边距。实测“取消”贴到左边界，底部及正文还重复预留空间。
- 列表外层 article 和共享记录行都设置 padding，重复压缩了完整名称、联系方式与金额的空间。
- 普通下拉选项是 role=option 的元素，不是 button，原手机按钮触控规则未覆盖；搜索清除按钮扩大到 44px 后，原 36px 文本内边距也不够。

## 统一尺度

沿用 `tokens.css` 的字体、间距和颜色，不新增手机主题：

- 页标题 18px；模块/弹窗标题 16px；正文和动作文案 14px；辅助信息 12–13px。
- 可编辑输入继续使用 16px，保留上轮苹果输入兼容；不将所有页面文字都放大。
- 普通输入和选择控件 44px；图标按钮 44×44px，图形 20px。
- 底部主操作及选项行至少 48px；较长的名称允许控件自然增高，不缩小字体或裁掉内容。
- 记录缩略图 44px，列表行最低 68px，完整名称、状态和金额沿用原数据。

修复落在既有 `globals.css` 手机断点及基础组件：

- 手机控制变量移到 `:root`，页面和 Portal 共用。
- 页头通用宽度规则不再压缩图标动作，并显式锁定手机图标触控宽度。
- Button 只增加语义 variant 标记，让底部主操作按角色设尺寸，不根据颜色类名猜测。
- ErpDialogShell 标记 header/body/footer；外置底栏清除负边距，正文不再重复留整条操作栏高度。桌面仍用原样式。
- ErpSearchInput 增加 clear 标记，手机有清除按钮时预留 52px 文本空间。
- 普通 Select 的手机选项行至少 48px，长标签可换行，弹层不被桌面锚点最小宽度撑大。
- 移除手机领域列表 article 的第二层 padding，记录行独立负责其内边距。

## 最终构建实测

测试使用 `127.0.0.1:3020` 的 LOCAL-ONLY 合成数据。没有创建客户、销售单、采购单或资金记录；用户原表单未重新加载或提交。浏览器视口模拟不代表真实手机硬件验收。

### 页面尺寸

320×740、390×844、430×932：分别检查首页、库存、商品库、采购开单、销售开单、质检、客户档案、销售毛利、资金账户、员工权限，共 30 个页面/尺寸组合。

- 最终页面文档宽度未超过视口。
- 当前可见的共用图标动作没有小于 44×44px 的目标。
- 使用当前页面可见标题等待加载，排除了早期异步切换中读到旧页面的结果。

768×900、1024×900、1440×900：检查客户、采购新建、销售新建。控制高度恢复 40px，手机底部导航不显示，文档无横向溢出；1024/1440 的采购和销售仍是原四行编辑表格。

首次桌面视口切换实际仍为 390px，已排除；后续在新独立标签中先核验 `innerWidth` 再完成上述桌面验收，不用手机结果冒充桌面结果。

### 真实交互和几何

- 客户“更多”由 20px 宽修复为 44×44px；客户记录可用宽度由 300px 增至 324px（390px 视口）。
- 新建客户：全部普通输入/Select 为 44px，输入文字 16px，标题 16px；外置底栏 margin=0，左右按钮与正文同样留边，主操作 48px。
- 320px 客户类型选项：7 项均为 48px，弹层左右边界 12/308px；实际选择“个人卖家客户”后值正确。
- 390px 搜索：清除动作 44×44px，文本 padding-right=52px；点击清除后恢复空查询。
- 320px 采购、销售分别通过原客户/来源和商品选择器录入并进入结算。输入高 44px、字体 16px；下一步与提交主操作高 48px，右边界 308px，按钮底部约 667.5px，主导航顶部 680px，没有重叠。
- 320px 销售三档收款选项各约 75px 宽、44px 高、14px 字体，保持一行可点选。
- 最终测试页未捕获 warning/error。
