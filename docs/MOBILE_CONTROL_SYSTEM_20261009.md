# 移动控件全局规则与复用清单

适用范围：手机宽度小于 768px。沿用现有 `tokens.css`、`globals.css` 和组件目录；不增加第二套移动主题，不改业务数据或金额算法。

## 尺寸规则

| 控件 | 手机规则 | 统一来源 |
| --- | --- | --- |
| 普通按钮、输入、金额、选择触发器 | 最小触控高度 44px；长文字自然增高 | `--erp-mobile-control-height` |
| 返回、关闭、清空、数量加减 | 最小 44×44px，图标 20px | `--erp-mobile-touch-size`、`--erp-mobile-icon-size` |
| 底部提交、弹窗主要操作 | 最小高度 48px | `--erp-mobile-primary-height` |
| 普通选择菜单选项 | 最小高度 48px，长名称换行不截断 | `--erp-mobile-option-height` |
| 文本、金额、搜索、多行输入 | 16px；数字继续使用等宽数字特性 | `--erp-mobile-input-text` |
| 复选、单选 | 整个 Label 最小高度 44px；标记 20px | `--erp-mobile-choice-size` |
| 多行输入 | 最小高度 96px，可继续增高 | `--erp-mobile-textarea-height` |
| 日期网格 | 日期触控高度 44px，七列宽度随容器分配；翻月按钮 44×44px | `ErpCalendar`、`--erp-mobile-touch-size` |
| 标签、普通正文、说明 | 保持现有 14px 正文和 12–13px 辅助信息 | 原有 Typography Token |

44/48 都是最小触控尺寸，不是强制固定高度。不要用固定高度把长名称挤成一行。状态 Badge 不是按钮，不需要放大成 44px；日期网格使用其公共组件规则，不对每个日期强加普通按钮宽度。

共享按钮的手机规则通过 `data-erp-control="button"` 生效，包含 Portal 中的按钮。输入、选择、复选和数量组件通过现有语义标记生效；大于等于 768px 不应用手机尺寸覆盖。

## 弹层与键盘规则

- 少量固定选项继续使用统一 `Select` 的底部菜单；客户、商品和需要检索的单据采用已有全屏选择界面。
- 搜索栏属于固定工具区，不放进结果滚动区。`ErpDialogShell.toolbar` 与 `dialog-body` 分离，页头、工具区、页脚不收缩，只有结果列表滚动。
- 打开手机选择器不自动聚焦搜索框。用户主动点搜索时才弹键盘，避免单个账户选项也触发键盘。
- 继续使用项目已有的可视窗口高度、键盘高度与安全区服务，不重复注册每个页面的键盘监听。相关浏览器机制参考 [VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)。
- 浏览器缩短视口验收不等于 iPhone 真机键盘验收。Safari/PWA、中文输入法、横屏和键盘关闭后的恢复仍需真机测试。

## 已收敛的复用

| 用途 | 权威组件 | 本轮结果 |
| --- | --- | --- |
| 文本搜索与清空 | `ErpSearchInput` / UI 内部 `SearchInput` | 同一实现；检索 Select 不再复制搜索图标和输入框 |
| 客户/采购来源选择 | `CustomerPicker` | 共用弹层工具区和搜索控件 |
| 商品/库存选择 | `InventoryItemPicker`、搜索型 `Select` | 固定搜索区，不强制打开键盘 |
| 账户选择 | `AccountPicker` → `Select` | 保持原系统控件，继承触控和长标签规则 |
| 全额/未付/部分结算 | `ErpSegmentedControl` | 采购和销售共用；计算及权限仍归原领域 |
| 数量加减 | `ErpQuantityStepper` | 保留原数量校验，统一加减触控区，补齐公共出口 |
| 单选/复选 | `ErpCheckboxField`、`ErpRadioField`、`ErpRadioGroup` | 整行可点，不仅小方框可点 |
| 金额、日期、多行备注 | `ErpAmountInput`、已有日期组件、`Textarea` | 继续复用原实现，不增加移动版副本 |

## 后续可复用，但不机械替换的区域

- 库存的视图切换、首页的日期范围切换可以评估 `ErpSegmentedControl`，仅适合互斥选择；路由 Tab 不应被当成普通分段按钮替换。
- 销售、采购和退货的底部主操作继续优先复用 `ErpSubmitBar`、`ErpMobileWorkflow` 或现有 Action Dock；不要每页新建 fixed 底栏。
- 高信息密度选项允许领域组件保留商品图片、SN 和库存状态，但搜索框、弹层结构、触控尺寸不应各自复制。

## 验收与守护

- 本地 `__design-system` 增加控件尺寸样例：普通/小/禁用/图标按钮、搜索、数量、结算分段、单选复选、长账户名称及备注；不进入生产菜单。
- 设计系统检查要求手机语义 Token 存在；组件测试守护搜索单实现、禁用状态、固定工具区、无强制自动聚焦和两个付款区的复用。
- 尺寸矩阵：320、390、430px 手机；768px 断点；1440px 桌面。补充缩短高度的选择器测试，检查搜索、返回、结果区各自可达。
- 真实业务回归重点：客户选择、商品检索、数量增减、全额/部分/未付款切换、账户选择、日期和弹窗取消。测试只用本地合成数据，不生成真实业务单据。

## 本轮验收结果（2026-10-09）

- 已在本地构建预览中检查 320、390、430px 手机宽度，以及 768、1440px 桌面宽度。样例控件和采购结算区域未出现横向溢出；手机普通/图标按钮为 44px，输入为 44px / 16px，底部提交为 48px。桌面普通按钮仍为 40px、输入字体仍为 14px。
- 长账户名称可换行增高；搜索型和普通选择菜单选项最小高度为 48px。公共单选复选标记、销售页原生复选框均为 20px，销售复选框整行触控高度为 44px。
- 320×420px 的缩短窗口中，搜索型选择器页头为 61px、搜索区为 69px，二者不收缩，剩余区域滚动；输入 `4090` 后仍能选择匹配商品。此测试不模拟真实系统键盘。
- 320px 日期选择器七列没有横向溢出，日期按钮约 36.4×44px，翻月按钮为 44×44px；选中日期能回写原控件。超窄屏的日期列宽是有意保留的网格例外，不宣称每列都有 44px 宽。
- 采购和销售的客户/来源、商品选择、数量、全额/未付/部分结算和账户选择已使用本地合成数据回归；没有提交采购单或销售单，没有访问生产业务数据。
- 完整测试曾通过 1491 项、跳过 37 项（共 1528 项）；最后日期和原生复选框补充后，33 项专项测试全部通过。最终 `npm run lint`、`npm run build` 和 `git diff --check` 均通过。数据库集成跳过项不计为通过。
- 本次未上线。待真机检查：iPhone Safari / 主屏幕模式、中文输入法、键盘展开与关闭、横屏和安全区恢复；不能把短窗口测试作为这些边界的完成证明。
