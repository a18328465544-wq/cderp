# 商业化 API Gap

这份清单记录本轮没有通过新增后端业务能力解决的事项。它们不是前端隐藏问题，也不能用 UI 状态代替服务端约束。

| 优先级 | 缺口 | 当前行为 | 商业化要求 |
| --- | --- | --- | --- |
| P0 | 全局账号身份规范化 | `gpu_system_users` 兼容历史租户/门店列，成员表负责授权 | 迁移到全局 identity + tenant membership，保证跨企业登录、账号修改和成员列表语义一致 |
| P1 | 产品候选服务端分页 | `/api/products` 默认保持历史整集合响应 | 增加分页、关键字和权限投影接口，避免超大商品库一次性载入 |
| P1 | 媒体孤儿回收 | 关系删除后资源保留，防止误删仍被引用的媒体 | 增加引用计数/保留期、管理员确认和可恢复回收任务 |
| P1 | 租户级异步导出 | 当前导出同步生成当前请求可见门店快照 | 多门店全量导出、异步任务、过期清理和对象存储下载 |
| P1 | 业务写操作全量幂等覆盖 | 核心单据和关键财务创建已支持 `Idempotency-Key` | 为所有外部导入、库存批处理和异步重试命令定义统一幂等契约 |
| P2 | 支付订阅 | 只有套餐/用量控制面，无支付提供商写入 | webhook 签名、事件去重、欠费/退款状态和账单对账 |
| P2 | 外部错误聚合 | 结构化日志和 `/api/ops/metrics` | 接入 Sentry/Datadog 等平台，脱敏并关联 request ID、发布版本和操作日志 |
| P2 | SSO/SCIM | 仅账号密码和成员关系 | 企业身份提供商、邀请生命周期、离职回收和审计 |
| P2 | 多副本/多区域 | 单 PM2 fork + PostgreSQL | 共享缓存/会话、读模型、队列、故障切换和跨区域恢复目标 |

任何缺口在获得对应 API/供应商能力前，不得由前端伪造成功状态、余额、用量、支付或权限。
