# 检测质检 API Gap

## 当前可用但需要前端降级的能力

### 1. 缺少检测工作台专用读取接口

当前待检测库存和历史检测记录只能通过：

```text
GET /api/inspections/workspace
```

获取。

影响：

- 数据量增长后，首屏下载和 Adapter 转换成本会线性增加。
- 无法进行真正的服务端分页、筛选、排序和关键字搜索。
- 页面当前明确标注为状态快照兼容模式，不伪装成服务端能力。

未来建议提供只读接口：

```text
GET /api/inspections/workspace
GET /api/inspections?page=&pageSize=&keyword=&resultStatus=
GET /api/inspections/:id
```

## 权限与敏感字段

状态快照由后端按现有权限裁剪。检测 Adapter 不读取也不暴露库存成本、预计售价或利润字段。

仍需后端长期保证：无成本/利润权限的账号在 `/api/inspections/workspace` 中不会收到对应敏感字段；前端隐藏不等于数据安全。

## 历史检测单修改

后端存在：

```text
PUT /api/inspections/:id
```

修改历史检测记录会同步改动库存 SN、状态和属性，属于高风险操作。当前路由已接入现有 `canEditHistory` 历史编辑权限，前端也只向具备该权限的账号展示编辑入口；这不等于完成了历史版本治理，后续仍需单独审计：

- 编辑权限与角色/门店数据范围的长期治理。
- 已销售、已退货、维修中库存是否允许回改。
- 历史成本因“降价入库”变化后如何冲销。
- 并发修改和审计展示。
- 检测记录版本链、可逆回滚与冲突校验。

## 媒体能力

现有写接口具备检测证据媒体处理能力，但 V1 检测页面没有完整上传交互。本轮按能力等价迁移未新增检测证据上传，避免在未审计媒体生命周期前扩大范围。

后续如实施，需要复用既有媒体上传、压缩和删除规则，不创建第二套上传系统。
