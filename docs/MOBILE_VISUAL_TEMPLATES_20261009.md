# 移动 UI 四类视觉模板

适用范围：宽度小于 768px 的手机界面。建立在现有 [移动控件规则](MOBILE_CONTROL_SYSTEM_20261009.md) 上，继续复用 `tokens.css`、`globals.css`、公共控件和领域选择器。本轮不调整桌面 / 平板布局、业务计算、权限、路由或接口。

## 统一节奏

- 页标题 20px / 600，模块标题 16px / 500，正文 14px / 400，字段名称 13px / 500，辅助信息 12px / 400。可编辑输入仍为 16px，避免为追求密度缩小输入文字。
- 主要内容水平留白 16px，模块间距及列表纵向留白 12px；直接引用原有字号与间距 Token，不建立另一套数值体系。
- 金额继续使用等宽数字特性，不换代码字体、不截断、不转换成“万”。商品全称、SN 和关联单据允许完整换行；成色等短字段不在词内拆分。
- 普通触控区至少 44px，底部主要操作至少 48px。信息行允许自然增高，不能用固定高度换取整齐。

新增别名为 `--erp-mobile-page-title`、`--erp-mobile-section-title`、`--erp-mobile-field-label`、`--erp-mobile-content-inset`、`--erp-mobile-section-gap`、`--erp-mobile-row-inset`。其值全部引用现有 Token，使用规则全部限定于手机媒体查询。

## 四类模板与复用入口

| 模板 | 视觉规则 | 沿用组件 |
| --- | --- | --- |
| 开单 | 来源 / 客户、商品、结算层次一致；减少嵌套边框；可选信息展开后不再包第二层卡片；底部保持金额汇总与一个主操作 | `ErpMobileWorkflow`、`ErpMobileOrderLine`、`ErpSubmitBar`、`ErpSegmentedControl`、原金额 / 数量 / 账户控件 |
| 选择器 | 固定选项使用原底部菜单；可搜索内容使用原全屏选择器；搜索区固定、结果独立滚动；完整主名称 14px / 500，辅助描述次级显示 | `Select`、`PhoneSearchSelect`、`CustomerPicker`、`InventoryItemPicker`、`ErpSearchInput` |
| 列表 | 一块连续白色列表面，行间细分隔线；消除每条记录独立灰卡、阴影及重复间距；不隐藏领域状态、价格或 SN | `ErpMobileRecordRow`、原客户 / 库存领域行、`data-mobile-projection="list"` |
| 详情 | 外层负责内容留白；模块依次排列并用细分隔线区分；字段采用左标签、右值单列行；减少卡片套卡片，保留风险和金额语义色 | `ErpDetailDrawer`、`ErpDetailFact`、`ErpDetailFactGrid`、`InventoryJourneyPanel` |

新增 `data-erp-component` / `data-erp-region` 仅作为统一样式入口，不改变组件状态或事件。客户 / 库存专属内容继续属于领域组件；不得为统一样式复制领域选择、金额计算或校验逻辑。

## 本轮验证

使用本地构建产物与合成数据，不提交真实采购、销售或资金操作，不访问生产业务数据。

- 320、390、430px 手机窗口检查列表、选择器、详情及开单：完整型号、长客户名称、长 SN、大金额未造成页面横向溢出。长记录自然增高，金额保持完整。
- 320×420px 缩短窗口检查搜索选择器：页头、搜索区不收缩，结果独立滚动；输入 `4090` 后仍可选匹配商品，打开选择器不强制弹出键盘。
- 客户 / 库存空列表、客户加载失败与重试入口可见；主要操作为 48px。销售缺账户时原阻塞状态保持，选择账户后恢复就绪。
- 采购的数量与部分付款、销售的客户 / 商品 / 账户选择已回归；没有点击最终提交。
- 768px 保留既有平板卡片呈现，1440px 采购 / 销售保留原 4 行表格。检查未出现页面横向溢出，桌面控件高度仍为 40px。
- `npm test`：共 1534 项，1497 通过、37 跳过、0 失败。跳过的数据库 / HTTP 集成项不计为通过。
- 本地 lint、前后端构建、产物性能检查及差异检查通过；新增视觉契约测试守护 Token 的手机作用域、连续列表、完整字段和单一底部操作节奏。

## 未验证边界

这轮是本地 UI 收敛，不是生产部署或真实账务写入验收。iPhone Safari / 主屏幕模式、中文输入法、真实键盘展开 / 关闭、横屏以及安全区恢复仍需真机检查，缩短浏览器窗口不能替代这些验证。

## 第二轮：五项外观收敛

沿用以上四类模板，只调整小于 768px 的手机呈现。桌面 / 平板、业务字段、接口、金额计算、权限、选择器事件、提交和草稿行为不在本轮修改范围。

1. **身份与缩略图**：新增公共展示组件 `ErpEntityThumbnail`。客户使用姓名首字（英文前两个字符）的低饱和头像，底色仅由姓名稳定派生，与客户等级、风险无关。商品使用接口提供的真实图片；没有图片时按系统 12 类商品展示类目图标，未知类目回退包裹图标。图片加载失败也回退，不生成假商品图、不发起额外查询。列表与开单行默认 44px，客户详情 48px，库存详情无图时 64px；有真实图片才扩展展示区域。
2. **列表层级**：名称与金额为 14px / 500，成色与状态使用原语义，SN、日期、库位和金额标签为次要层级。完整金额及长名称 / SN 仍可自然排版，不转成“万”，不使用省略号换取整齐。
3. **开单边框**：采购 / 销售保留原金额、数量、账户等可编辑控件边框；只读显示、发票 / 运费勾选行、说明文字和可选汇总采用弱分隔。原校验提示、禁用和聚焦样式保留。
4. **详情主次**：客户、库存、采购与销售详情共用 `detail-hero` 样式入口，突出对象名称、当前状态和完整金额；日期、经办人、结算事实、关联库存与物流 / 备注仍沿用原字段。采购总额继续受原成本权限限制，销售 / 客户利润仍受原利润权限限制。桌面详情分支不改。
5. **按钮与标签**：筛选选中状态采用轻强调，主要业务动作保留蓝色；移除动作沿用危险语义色。标签统一 Token 字号、内边距和圆角，允许内容自然增高。保持普通操作 44px、主要操作 48px，输入文字仍为 16px。

### 复用规则

- `ErpEntityThumbnail` 属于 `common` 展示层，参数为 `name / kind / category / imageUrl / fallbackIcon / className`。已有业务图标可通过 `fallbackIcon` 保留，不将领域逻辑搬进头像组件。
- `ErpMobileRecordRow` 新增可选 `thumbnail`；原 `icon`、`imageUrl`、状态位置、金额、打开行为仍兼容。采购 / 销售的 `ErpMobileOrderLine` 只增加可选类目展示信息，仍使用功能页面传入的原价格 / 数量控件与回调。
- 所有外观值直接引用既有 Token；新增样式完全位于手机媒体查询内，不建立第二套尺寸 / 颜色系统。

### 本轮补充验证

- 本地构建与合成数据预览（3021–3024），全部业务写入被禁止；未连接生产数据库、未提交单据、未部署。
- 320 / 390 / 430px 检查客户、库存列表以及客户 / 库存详情；长姓名、长 SN、仓位及 `¥1,234,567,890` 完整，页面和行容器没有横向溢出。零售价仍为 `¥0`，缺失售价仍为“未设置”。
- 手机采购 / 销售选择原客户、来源、商品、账户；采购数量 1 → 2、部分付款 50 / 剩余欠款 150 保持原计算；销售缺账户仍阻止提交，选择账户后恢复就绪。未点击最终提交。
- 两个开单页的可编辑金额 / 数量为 16px、44px；销售只读勾选行仍有 44px 点击区，提交按钮为 48px。客户 / 库存空状态与客户读取失败、重试入口可见。
- 采购 / 销售单详情已核对对象、状态、日期、经办人、金额、明细及结算事实显示；补充信息保持折叠。
- 768px 客户仍使用既有平板卡片，没有手机头像行；1440px 采购 / 销售仍为原 4 行表格，金额 / 数量控件仍为 40px，未出现页面横向溢出。
- 完整自动回归：1554 项，1517 通过、37 跳过、0 失败；跳过的数据库 / HTTP 集成项不计为通过。lint、类型检查、前后端本地构建、产物性能预算与差异格式检查通过。新增测试守护首字 Unicode、12 类目、真实图片 / 缺图、手机作用域、有效 Token、只读摘要与原金额权限。
- 图片错误回退已检查实现与源代码契约，但未用真实图片故障做浏览器验收。真机键盘、iPhone 主屏幕和实际账务写入仍属于上面的未验证边界。
