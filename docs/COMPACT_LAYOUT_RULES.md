# OneERP V2 紧凑布局规则

## 目标

在不牺牲业务判断、权限提示和风险确认的前提下，把首屏空间优先留给真实数据、筛选和下一步操作。规则适用于所有 v2 页面、列表、看板、抽屉和表单。

## 文案分层

### Quick Status

- `QuickStatusGroup` 默认使用 `compact`，只保留 `icon + value + label` 的单行摘要。
- `description` 不得在 Compact 中常驻占一行；兼容字段应转为 Tooltip，真正的流程说明使用专门 Stepper 或显式 `workflow` 变体。
- 普通状态摘要不显示箭头；Dashboard、List、Finance、Inventory 和 Warehouse 页面不得用箭头制造流程感。
- Feature 不得复制 QuickStatus 布局，也不得添加页面专属 QuickStatus 高度、间距或颜色。

### 页面上保留

- 页面标题和当前模块状态。
- 会改变用户决策的风险、权限、合规和安全提示。
- 空状态、加载态、错误态和表单级校验结果。
- 操作结果、数据范围和必要的时间/数量上下文。

### 页面上移除或收起

- “当前接口返回……”“未伪装服务端分页”“由服务端最终校验”等实现细节。
- 重复导航、重复标题和“本页可以做什么”的介绍性段落。
- 表格标题下解释点击行、筛选、分页等已由控件本身表达的说明。
- 仅用于开发验收的契约、快照、适配层和兼容模式说明。

实现细节放入代码注释、设计文档或开发日志；如果确实影响用户判断，改成短状态标签或风险提示，不再占用独立说明条。

## 组件契约

- `ErpPageHeader` 默认 `density="compact"`：只显示标题、状态和操作；只有表单流程、安全边界或不可逆后果需要解释时才传 `density="default"`。
- `DashboardSection` 默认 `density="compact"`：标题与操作同一行，隐藏区块说明，使用 16px 内边距和 12px 内容间距。
- `DashboardSection density="default"` 只用于决策上下文或安全说明，最多一行短句。
- 表格数量、筛选状态、加载来源优先使用 `ErpStatusBadge`、分页和空状态承载，不另起说明卡。
- 技术状态不得出现在用户可见的 quick status 文案中；“真实整库、未伪装分页”等信息只进入开发文档或调试面板。
- 字段级校验文本、帮助注解和可选辅助文案不得直接插入控件下方的流式布局；保留校验状态与提交阻断逻辑，反馈统一通过表单级错误、Toast 或 `role="alert"` 区域表达，避免撑高表格行和字段。页面/区块说明如果确有业务价值，必须使用固定的单行说明槽位（`erp-annotation-slot`）；没有文案时保留不可见槽位。下拉选项还必须统一预留第二行说明高度。

## 密度基线

| 区域 | 紧凑基线 | 默认基线 | 备注 |
| --- | --- | --- | --- |
| 页面标题 | 24px、无副标题 | 28px、最多一行副标题 | 列表页优先紧凑 |
| 区块卡片 | 16px 内边距 | 20px 内边距 | 不用 padding 填空 |
| 区块头部 | 12px 底部间距 | 16px 底部间距 | 标题、操作同一行 |
| 区块内容 | 12px 顶部间距 | 16px 顶部间距 | 表格首屏优先 |
| 说明文案 | 默认不渲染 | 一行、12px | 不能重复控件行为 |
| 页面分段 | 16px | 20px | 移动端降为 12px |

## 判断流程

新增或修改一段说明时，依次回答：

1. 删除这段话后，用户是否会做出错误或有风险的决定？
2. 这段话是否已经由标题、状态、字段标签或按钮表达？
3. 它是否描述实现方式，而不是业务结果？

第 1 题为“是”才保留；第 2 或第 3 题为“是”则删除或移到开发文档。无法判断时，优先保留为表单级错误或状态徽章，而不是新增一整行字段注解。

## 验收清单

- [ ] 列表页首屏没有独立的实现说明条。
- [ ] 标题、筛选、主操作和表格在首屏连续出现。
- [ ] 风险、权限、错误和空状态仍可见且能指导下一步。
- [ ] 1440px、1024px、390px 下没有因隐藏说明产生遮挡或不可达操作。
- [ ] 新增说明已选择 `density="default"`，并写明保留原因。
